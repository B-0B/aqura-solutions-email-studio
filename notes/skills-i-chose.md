# Skills I Chose

## Use these

**For writing campaigns: `coreyhaines31/marketingskills`**
This repo has skills for email copy (`@emails`), cold outreach (`@cold-email`), and onboarding CRO. There was a separate `@email-sequence` skill, but it has been merged into `@emails`; skills.sh still lists it, though the repo no longer has an email-sequence folder. Corey Haines is a known SaaS marketer (corey.co) with 3,700+ GitHub followers. The repo has 59,500+ stars and 8,700 forks — active community, MIT-licensed, created Jan 2026 and still getting updates. The install counts on skills.sh (53K–136K per skill) back this up.

**For sending email: `resend/resend-skills`**
This is the official Resend organization (resend.com), the same team behind `react-email` (20,000 stars). Their skills include `@resend` for sending, `@resend-cli` for the CLI, and `@agent-email-inbox` for receiving. They also publish `resend/react-email` and `resend/email-best-practices` as separate repos. All first-party, all from a company whose entire product is email infrastructure.

## Avoid these

**`caffeinelabs/skills` (`@extension-email-marketing`)**
The GitHub repo has 2 stars and no description. 30,900 installs on skills.sh looks decent until you see there's essentially no community, no documentation, and no indication of who caffeinelabs is. High install count with no GitHub engagement is a red flag.

**`open.feishu.cn/lark-mail`**
879,800 installs — the highest in the search — but almost every Lark skill shows nearly the same count (lark-mail 881.1K, lark-whiteboard 880.9K, lark-event 880.8K), because they install together as a bundle. So the number reflects the Lark platform's install base, not demand for lark-mail specifically. This is also a Lark/Feishu skill (ByteDance's enterprise platform) — it's for Lark Mail, not general email marketing. The publisher isn't a standard GitHub org, and the skill wouldn't integrate with Western email providers like Resend, SendGrid, or Mailchimp.

## How I decided

Three things to check before installing any skill:

1. **Who publishes it.** Look up the GitHub org or user. An official product org (like `resend`) or a person with a real identity and track record (like Corey Haines) is safer than an anonymous account. Cross-reference the org's website with the skill's claimed purpose.

2. **Stars and forks vs. install count.** A skill with high skills.sh installs but almost no GitHub stars (like caffeinelabs at 2 stars / 30K installs) suggests the repo hasn't been vetted by developers. Stars alone aren't proof of quality, but a healthy ratio of stars, forks, and open issues signals real community oversight.

3. **Scope and fit.** Even a trustworthy skill can be wrong for your project. Lark Mail is legitimate software, but it's for a different ecosystem. Check that the skill targets the tools and providers you actually use — don't install a platform-specific skill when a general-purpose one exists.
